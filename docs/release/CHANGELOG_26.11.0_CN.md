# MeowEco Economy 26.11.0

发布日期：2026-11-13

这是从 `26.10.7` 升级的功能版本：新增初始赠币来源追踪、可选的签名身份初始赠额，以及供玩家商店接入的交易扣款与幂等退款 API，同时修复 26.x 服务端收到 1.21.11 分支更新提示的问题。新增功能和 API，因此版本号提升为 `26.11.0`。

## Added / 新增

- **初始赠币来源账本**：在总余额之外记录尚未花掉的赠额，来源和来源审计与余额变更在同一事务提交或回滚。
- **赠币转账与消费顺序配置**：`initial-funds.allow-player-transfer` 默认 `false`；`spending-order` 默认 `GIFT_FIRST`，也支持 `EARNED_FIRST`，可通过 `/meco reload` 生效。
- **可选签名身份赠额**：通过 MeowIdentity 签名会话桥与 PlaceholderAPI，为新钱包设置离线基础额和正版总赠额；先发基础额，确认正版后只补一次差额。示例为 100/1000，默认关闭，相关桥接插件不随 MeowEco 提供。
- **玩家交易 API**：`getInitialGiftBalance`、`getTransferableBalance`、`withdrawForPlayerTrade`，供商店原子检查并扣除可交易来源。
- **持久化支付收据 API**：`debitWithReceipt`、`getReceiptState`、`refundReceipt`；同一引用重试不重复扣款，退款只回原钱包一次并恢复原赠额标签，冲突参数复用引用会失败。
- **回归覆盖**：身份延迟与一次性补差、消费顺序、转账、兑换、冻结与管理扣款、导入覆盖、审计失败回滚、收据防重、双实例与重启，以及更新筛选和 Vault 异步异常清理。

## Changed / 变更

- 新建且符合配置的初始余额、后续正版补差开始记录来源；旧钱包的未知来源不会猜测回填，不重置玩家已有余额。
- 默认赠币可以自行消费，但不能直接 `/pay` 给其他玩家。允许赠币转账时，收款方继续保留相应赠币标签；货币兑换也按比例保留来源。
- 冻结金额保守地从可转出的赚取余额中扣除；普通扣款、管理扣款和迁移减额遵循消费顺序。
- 普通 Vault 扣款继续按个人消费规则处理。**Vault 不包含交易目的或收款方，第三方玩家商店必须明确接入玩家交易 API，才会执行赠币交易限制；普通 Vault 入账退款视为赚取余额。**
- 更新检查同时按实际 Minecraft 版本和 Paper 加载器筛选，并从兼容版本中选择最高插件版本，不再直接取最新上传记录。
- 同步更新项目介绍、发布页面说明、中英文更新日志，并在 JAR 中保留 MIT 许可证。
- 原有通胀报告、阶梯富人税与转账税、多货币、Classic Vault、VaultUnlocked v2、迁移和 SQL 存储功能继续保留；本次不调整既有税率。

## Fixed / 修复

- 修复 26.x 服务端被提示更新到仅支持 Minecraft 1.21.11 的 `26.10.7.1-mc1.21.11`。
- 修复点分版本号的数字比较；`+maowo.2` 等构建信息及 `-mc1.21.11` 目标后缀不会再拼入版本数字。
- 防止重连、重启或多实例并发重复补发身份赠额，避免用设定总余额的方式覆盖期间消费、收入或冻结资金。
- 防止通过兑换或允许的直接转账丢失赠币来源，以及重复退款、引用冲突或审计失败造成余额异常。
- `/pay` 因赠币不可转出而失败时，提供中英文原因提示。
- 修复命令注册、玩家查询、更新通知、格式化、迁移和测试中的空值诊断，并完善 Vault 异步任务返回 null 或抛异常时的 future 完成与操作清理。

## 升级与回退

- 升级前备份数据库与配置。支持 Paper 26.1 / 26.1.1 / 26.1.2 / 26.2 / 26.3，要求 Java 25；Purpur 按对应 Paper 版本兼容。
- 新增独立赠额、来源审计及支付收据表，原账户和历史余额不批量重写；旧钱包不追溯补币。待确认赠额沿用创建时金额，调价只影响以后新建钱包。
- 不启用身份赠额时，仍使用货币原有 `initial-balance`；新发放且符合配置的初始金额会记录来源，并适用默认赠币转账限制。
- 如需放开赠币转账，可在当前版本修改配置。旧版 JAR 不维护来源标签与支付收据；降级期间发生交易后，重新启用来源限制前需要核对账本。不要用旧数据库覆盖升级后的玩家交易，也不要清理仍用于防重的收据。

## 验证

- 完整 Gradle build：核心经济、SQLite、迁移、Classic Vault、VaultUnlocked v2 及更新检查回归。
- Paper 26.1.1、26.1.2、26.2 兼容编译，主构建使用 Paper 26.3。
- 实际 Modrinth 查询确认按 26.2 / Paper 筛选会排除 1.21.11 分支；多条 26.x 版本的筛选由回归覆盖。
- 本次新来源账本与收据功能经过 SQLite 实库验证，未新增实际 MySQL 集成验收；Purpur 未单独实服验证。
